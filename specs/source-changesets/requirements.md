# RM-SCM requirements

| ID | Requirement | Verification |
|---|---|---|
| `RM-SCM-R001` | **Import git history into engine changesets (rollup).** The tool must import the full history of one repository into engine changesets. Each commit becomes one changeset with the same tree hash, per `MEDULLA-SCM-R010`. Children `.1` to `.6` deliver it. Production call site: `rm_source_import` registered in `MCP_TOOL_REGISTRY` (`repository_manager/mcp_tools/registry.py:105`). | Satisfied only when its child rows are verified. |
| `RM-SCM-R001.1` | **Model.** `ImportPlan{repo, remote, refs, first_commit, last_commit}` and `ImportReceipt{repo, commits, changesets, tree_hash_matches}` are frozen pydantic models, as in `repository_manager/materialization/models.py:113`. Caller chain: `rm_source_import` (planned, `repository_manager/mcp_tools/source.py`) parses its arguments into `ImportPlan`, and `import_history` (planned, `repository_manager/source_changesets/importer.py`) returns `ImportReceipt`. Shape: both types live in `repository_manager/source_changesets/models.py` (planned) with `extra="forbid"` and `frozen=True`, and the canonical digest of a receipt reuses `canonical_digest` (`repository_manager/development/serialization.py:110`). The package `repository_manager/source_changesets/` does not exist yet. | Test: `tests/source_changesets/test_models.py::test_import_models_round_trip` (planned). It round-trips both models. |
| `RM-SCM-R001.2` | **Behavior.** The import walks commits in topological order and submits one changeset per commit through the SDK source client of `SCION-SCM-R001`. A re-run imports only new commits. Each changeset keeps the author, the message and the trailers. Caller chain: `import_history` (planned, `repository_manager/source_changesets/importer.py`) lists commits with `git rev-list --topo-order --reverse` through `Git.git_action` (`repository_manager/repository_manager.py:2462`), reads each commit's tree id, and calls `SourceClient` (`scion_sdk/source/client.py:84` in the SDK) `.commit` (:160) with the commit's message, which keeps the trailers. Shape: the already-imported set comes from the SDK client's `history` read (:108) so no second store exists; the engine side of the same mapping is `MEDULLA-SCM-R010`, whose served `ImportGitHistory` stream method is the alternative path and the choice between the two is an owner decision. Depends: `RM-SCM-R001.1`. | Test: `tests/source_changesets/test_import.py::test_import_is_incremental` (planned). It imports a 50-commit fixture twice and asserts 50 changesets, then 0. |
| `RM-SCM-R001.3` | **Wiring.** The served tool `rm_source_import` calls the import. arbora serves it as a connector tool behind admission (`ARBORA-OPS-R848`). Caller chain: arbora MCP calls the fleet connector `repository-manager`, whose server is built at `repository_manager/mcp_server.py:973`; `register_source_tools` (planned, `repository_manager/mcp_tools/source.py`) is an entry of `MCP_TOOL_REGISTRY` (`repository_manager/mcp_tools/registry.py:105`), reached through `register_split_action_tools` (`repository_manager/mcp_server.py:994`), and registers `rm_source_import`, which calls `import_history`. Shape: the registrar follows `register_merge_queue_tools` (`repository_manager/mcp_tools/merge_queue.py:16`): one `@mcp.tool` with typed arguments, the engine client of the caller passed to the SDK client, no engine call of its own. Depends: `RM-SCM-R001.2`. | Test: `tests/source_changesets/test_import_served.py::test_rm_source_import_returns_receipt` (planned). It calls `rm_source_import` through the MCP client and reads the receipt. |
| `RM-SCM-R001.4` | **Refusal.** A tree hash mismatch stops the import with `IMPORT_TREE_MISMATCH` and keeps prior changesets. A shallow clone refuses with `IMPORT_SHALLOW_HISTORY`. Caller chain: `import_history` (planned, `repository_manager/source_changesets/importer.py`) checks `git rev-parse --is-shallow-repository` before the walk and compares the returned changeset tree id with the commit tree id after each submission. Shape: both codes are members of one `ImportRefusal` string enum in `repository_manager/source_changesets/models.py` (planned), raised as a typed refusal and rendered by the tool; the check reuses the shallow detection idea of `_reject_divergent_state` (`repository_manager/history_identity/discovery.py:124`). Writes: none after the refusal. Depends: `RM-SCM-R001.2`. | Test: `tests/source_changesets/test_import.py::test_refusals_leave_no_partial_changeset` (planned). It asserts each code and no partial changeset. |
| `RM-SCM-R001.5` | **Evidence.** The receipt names the repository, the commit range, the changeset count and the tree hash result for each commit. Caller chain: `import_history` (planned) builds `ImportReceipt` from the per-commit results and `rm_source_import` returns it. Shape: the fields are those of `ImportReceipt` in `repository_manager/source_changesets/models.py` (planned); `tree_hash_matches` holds one boolean per commit in walk order. Depends: `RM-SCM-R001.1`. | Test: `tests/source_changesets/test_import.py::test_receipt_fields` (planned). It reads the receipt fields. |
| `RM-SCM-R001.6` | **Hot-path proof.** The entry point is the served `rm_source_import`. The test imports a 1,000-commit fixture and must finish under 120 s and 512 MiB. Caller chain: the MCP client calls `rm_source_import` (`RM-SCM-R001.3`), then `import_history`, then the SDK client against a recorded engine. Shape: the fixture is built with temporary Git repositories as `tests/history_identity_git_fixtures.py` does. Depends: `RM-SCM-R001.3`. | Test: `tests/source_changesets/test_import_served.py::test_import_full_history` (planned). It asserts the time and memory bounds. |
| `RM-SCM-R002` | **Mirror sync to the public git hosts (rollup).** The tool must export each landed changeset to the public and internal git mirrors and pull a commit made on a mirror back as a changeset. Children `.1` to `.6` deliver it. Production call site: `rm_source_land` (`RM-SCM-R003.1`) calls `mirror_changeset` after a landed receipt. | Satisfied only when its child rows are verified. |
| `RM-SCM-R002.1` | **Model.** `MirrorTarget{repo, host, remote, branch}` and `MirrorReceipt{changeset_id, commit_sha, tree_hash, host}` are frozen pydantic models. Caller chain: `mirror_changeset` (planned, `repository_manager/source_changesets/mirror.py`) takes `MirrorTarget` values and returns one `MirrorReceipt` per host. Shape: both types live in `repository_manager/source_changesets/models.py` (planned), shaped like the models of `RM-SCM-R001.1`. Depends: `RM-SCM-R001.1`. | Test: `tests/source_changesets/test_models.py::test_mirror_models_round_trip` (planned). It round-trips both models. |
| `RM-SCM-R002.2` | **Behavior.** After `source.land`, the sync pushes the exported commit to each mirror within 60 s. A commit made on a mirror imports as one changeset through `RM-SCM-R001`. The commit tree hash equals the changeset tree hash. Caller chain: `rm_source_land` (planned, `repository_manager/mcp_tools/source.py`) calls `SourceClient` (`scion_sdk/source/client.py:84` in the SDK) `.land` (:163) and, on a landed receipt, `mirror_changeset` (planned, `repository_manager/source_changesets/mirror.py`), which fetches the commit from the git bridge (`ARBORA-OPS-R851`) and runs `git push` without `--force` to each target through `Git.git_action` (`repository_manager/repository_manager.py:2462`); the pull-back runs `import_history` on the mirror's new commits. Shape: a landing made through another client than `rm_source_land` is not seen by this trigger; how such landings reach the sync (event or poll) is an owner decision. Depends: `RM-SCM-R001.2`, `RM-SCM-R002.1`. | Test: `tests/source_changesets/test_mirror.py::test_land_pushes_and_mirror_commit_imports_back` (planned). It lands one changeset and pulls one mirror commit back. |
| `RM-SCM-R002.3` | **Wiring.** The sync reads landed changesets through the SDK source client and uses the git bridge export of `ARBORA-OPS-R851` for the push. Caller chain: `mirror_changeset` (planned) calls `SourceClient` (`scion_sdk/source/client.py:84` in the SDK) `.history` (:108) and fetches over the bridge route `GET /git/{repository}/info/refs` and `POST /git/{repository}/git-upload-pack` that `ARBORA-OPS-R851` defines. Shape: the module reuses `Git.git_action` for every Git process and adds no HTTP client of its own beyond the bridge fetch through Git itself. Depends: `RM-SCM-R002.2`. | Test: `tests/source_changesets/test_mirror_sync_served.py::test_land_through_arbora_observes_mirror_push` (planned). It lands through arbora and observes the mirror push. |
| `RM-SCM-R002.4` | **Refusal.** A mirror that holds a diverged commit stops the sync with `MIRROR_DIVERGED`. The sync never force-pushes. Caller chain: `mirror_changeset` (planned) runs `git ls-remote` for the target branch and refuses when the remote tip is not an ancestor of the commit to push. Shape: `MIRROR_DIVERGED` is a member of a `MirrorRefusal` string enum in `repository_manager/source_changesets/models.py` (planned); the push argument list never contains `--force` or `--force-with-lease`. Writes: none after the refusal. Depends: `RM-SCM-R002.2`. | Test: `tests/source_changesets/test_mirror.py::test_diverged_mirror_refuses_without_push` (planned). It diverges a fixture mirror and asserts the code and no push. |
| `RM-SCM-R002.5` | **Evidence.** Each push writes one receipt per host with the changeset id, the commit SHA and the tree hash. Caller chain: `mirror_changeset` (planned) returns the `MirrorReceipt` list to `rm_source_land`, which returns it to the caller. Shape: fields as in `RM-SCM-R002.1`. Depends: `RM-SCM-R002.1`. | Test: `tests/source_changesets/test_mirror.py::test_receipts_per_host` (planned). It reads the receipts. |
| `RM-SCM-R002.6` | **Hot-path proof.** The entry point is a served `source.land`. The test observes the mirror commit within 60 s with an equal tree hash. Caller chain: the MCP client calls `rm_source_land` (`RM-SCM-R003.1`), then `mirror_changeset`, then a local bare repository standing for the mirror. Shape: the mirror is a temporary bare repository. Depends: `RM-SCM-R002.3`. | Test: `tests/source_changesets/test_mirror_sync_served.py::test_land_then_mirror` (planned). It asserts the 60 s bound and the equal tree hash. |
| `RM-SCM-R003` | **Served source development tools (rollup).** The connector must serve one tool per `source.*` operation: tree, blob, diff, history, blame, commit, land and revert. Each tool composes the SDK source client. Children `.1` to `.3` deliver it. Production call site: `register_source_tools` in `MCP_TOOL_REGISTRY` (`repository_manager/mcp_tools/registry.py:105`). | Satisfied only when its child rows are verified. |
| `RM-SCM-R003.1` | **Tools.** `rm_source_tree`, `rm_source_blob`, `rm_source_diff`, `rm_source_history`, `rm_source_blame`, `rm_source_commit`, `rm_source_land` and `rm_source_revert` are registered. Reads carry the read-only hint; writes carry the destructive hint. Caller chain: arbora MCP calls the connector (`repository_manager/mcp_server.py:973`), whose `MCP_TOOL_REGISTRY` entry `register_source_tools` (planned, `repository_manager/mcp_tools/source.py`) registers the eight tools. Shape: each tool is a thin adapter over the matching method of `SourceClient` (`scion_sdk/source/client.py:84` in the SDK): `tree` (:102), `diff` (:105), `history` (:108), `blame` (:111), `blob` (:114), `commit` (:160), `land` (:163), `revert` (:166); the registrar follows `register_merge_queue_tools` (`repository_manager/mcp_tools/merge_queue.py:16`), and the tool-schema fingerprints in `repository_manager/connectors/tool_schema_fingerprints.json` gain the eight entries. Depends: `RM-SCM-R001.3`. | Test: `tests/source_changesets/test_dev_tools.py::test_eight_tools_and_their_hints` (planned). It lists the eight tools and their hints. |
| `RM-SCM-R003.2` | **Refusal.** Each tool passes the typed refusal of `SCION-SCM-R001.4` through unchanged. A `conflict` refusal names the conflicting paths. Caller chain: the tool adapters of `RM-SCM-R003.1` catch the SDK refusal type and return it as the tool result. Shape: the closed reason codes are those of `SCION-SCM-R001.4` (`unauthorized`, `not_found`, `conflict`, `path_denied`, `oversized`, `deadline_exceeded`, `transport_unavailable`); the adapters map no code to another. Depends: `RM-SCM-R003.1`. | Test: `tests/source_changesets/test_dev_tools.py::test_conflict_refusal_passes_through_with_paths` (planned). It asserts a passed-through `conflict` with paths. |
| `RM-SCM-R003.3` | **Hot-path proof.** The entry point is arbora MCP. An agent edits one file through `rm_source_commit` and lands it through `rm_source_land`, per `MERISTEM-SCM-R001`. Caller chain: the MCP client calls `rm_source_commit`, then `rm_source_land`. Shape: one recorded engine; the assertion reads the landed file back through `rm_source_blob`. Depends: `RM-SCM-R003.1`. | Test: `tests/source_changesets/test_dev_tools_served.py::test_commit_and_land_through_arbora` (planned). It commits and lands one file and reads it back. |
| `RM-SCM-R004` | **One migration wave step for one repository (rollup).** The connector must move one repository to engine-primary for a wave of `PIPE-GATES-R006` and back to git-primary. Children `.1` to `.3` deliver it. Production call site: a planned `rm_source_wave_step` tool in `register_source_tools`. | Satisfied only when its child rows are verified. |
| `RM-SCM-R004.1` | **Behavior.** The step imports history (`RM-SCM-R001`), starts the mirror sync (`RM-SCM-R002`) and records the repository as engine-primary. The reverse step stops intake and records git-primary. Caller chain: `rm_source_wave_step` (planned, `repository_manager/mcp_tools/source.py`) calls `wave_step` (planned, `repository_manager/source_changesets/wave.py`), which calls `import_history` and then enables `mirror_changeset` for the repository. Shape: the primary side is recorded in the wave receipt only; the store that holds it across restarts is an owner decision (no state file exists in this package today). Depends: `RM-SCM-R001.2`, `RM-SCM-R002.2`. | Test: `tests/source_changesets/test_wave_step.py::test_step_and_reverse_on_a_fixture_repository` (planned). It runs the step and the reverse step. |
| `RM-SCM-R004.2` | **Refusal.** The step refuses with `WAVE_ENTRY_UNMET` when the wave entry criteria of `PIPE-GATES-R006` do not hold. Caller chain: `wave_step` (planned) evaluates the criteria before any import. Shape: how the criteria reach this connector (a passed argument or a read of the pipelines wave definition) is an owner decision; the refusal is a member of a `WaveRefusal` string enum in `repository_manager/source_changesets/models.py` (planned). Writes: none after the refusal. Depends: `RM-SCM-R004.1`. | Test: `tests/source_changesets/test_wave_step.py::test_unmet_entry_criterion_refuses` (planned). It asserts the refusal for an unmet criterion. |
| `RM-SCM-R004.3` | **Evidence.** The step writes a receipt with the wave, the repository, the primary side and the import receipt digest. Caller chain: `wave_step` (planned) returns the receipt to `rm_source_wave_step`. Shape: the receipt is a frozen model in `repository_manager/source_changesets/models.py` (planned) whose digest uses `canonical_digest` (`repository_manager/development/serialization.py:110`). Depends: `RM-SCM-R004.1`. | Test: `tests/source_changesets/test_wave_step.py::test_step_and_reverse_receipts` (planned). It asserts both receipts. |
