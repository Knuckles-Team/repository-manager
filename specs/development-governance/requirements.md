# RM-GOVERNANCE-001 requirements

Every requirement this specification owns, with the proof that closes it. Delivery state and
public evidence for each ID are recorded in [`status.json`](status.json); this file defines what
each ID means. The design is in [`spec.md`](spec.md) and [`plan.md`](plan.md), the test contract
in [`test-spec.md`](test-spec.md), and the work order in [`tasks.md`](tasks.md).

| ID | Requirement | Verification |
|---|---|---|
| `RM-GOVERNANCE-R001` | **repository-manager hosts the Git development-governance modules.** repository-manager's codebase contains the merge-queue, isolated-checkout lifecycle, and concept-reservation modules as the package's own governance implementation, consumed internally by its commit and queue tooling rather than duplicated elsewhere. | Verified by source and import tests confirming no parallel Git-governance implementation exists outside repository-manager's own modules. |
| `RM-GOVERNANCE-01` | **Single authority for Git development governance.** repository-manager owns branch lifecycle, isolated-checkout identity, merge-queue admission, and concept reservations as one authority that other packages call only through bounded APIs. | Verified by source and import tests confirming no parallel Git or branch-governance authority exists elsewhere. |
| `RM-GOVERNANCE-02` | **Branch allocation tracks ownership, lease, and lifecycle state.** repository-manager allocates an isolated branch record with repository ID, base commit, owner, lease/fence token, path allowlist, and lifecycle state, enforcing only legal state transitions and rejecting stale tokens. | Verified by tests that a concurrent allocation conflict and a stale heartbeat each fail without mutating existing state. |
| `RM-GOVERNANCE-03` | **Isolated checkouts never corrupt shared Git config.** repository-manager creates a real, separate Git checkout for each branch without modifying the shared repository's Git configuration, and serializes operations that touch the common repository so per-checkout state stays isolated. | Verified by a test that multiple concurrent checkouts remain usable and the shared repository's core.bare setting stays false. |
| `RM-GOVERNANCE-04` | **Commits stage only reviewed paths and verified gate identity.** A repository-manager commit stages only explicitly reviewed paths, runs its declared local gates, binds the resulting tree and gate identity together, and may enter the merge queue only from a clean, authorized branch checkout. | Verified by tests that an unrelated untracked file stays uncommitted and that a failing gate or a changed tree is refused admission. |
| `RM-GOVERNANCE-05` | **Merge-queue promotion rechecks identity before reporting success.** repository-manager's merge-queue promotion rechecks the base commit and validation identity before merging, records the outcome, and handles a conflict or a crashed process without ever reporting a merge that did not happen. | Verified by tests that a stale base, a conflicting patch, and a timeout each preserve the candidate for recovery rather than silently failing. |
| `RM-GOVERNANCE-06` | **Cleanup proves containment before deleting a branch checkout.** repository-manager cleanup proves that a branch's commits are contained in the target before removal, or else keeps a durable recovery anchor, and never deletes an unmerged or dirty branch checkout by default. | Verified by tests that an unsafe cleanup attempt is refused while a safe cleanup removes only its own checkout and the branch it merged. |
| `RM-GOVERNANCE-07` | **Concept reservations are scoped and cannot be silently reused.** repository-manager scopes each concept reservation to its repository and candidate identity, expires or releases it safely, and never allows it to be silently reused by a different actor. | Verified by tests that a duplicate or stale reservation claim fails with a typed conflict and offers a reconciliation path. |
| `RM-GOVERNANCE-R002` | **readme-deploy-block hook must not silently skip.** The readme-deploy-block hook must run its check and fail closed, not silently skip (fail-open), when invoked from an isolated branch checkout rather than the primary repository checkout. | Verified by a regression test that runs the hook from an isolated checkout and asserts it still executes its check. |
| `RM-GOVERNANCE-R003` | **Cleanup removes isolated checkouts and scratch only after merge.** After a branch is fast-forwarded and fully contained in main with no uncommitted or untracked files, repository-manager removes its isolated checkout, local branch, backup references, and any host-local build scratch, and keeps a log of the cleanup run. | Verified by a test that cleanup proceeds only once containment and a clean tree are confirmed, and that a log record is produced. |
| `RM-GOVERNANCE-R004` | **Workspace check refuses credential-embedded remote URLs.** repository-manager provides a check that refuses any Git remote URL embedding a username or token credential, strips such credentials from remote URLs it manages, and directs authentication through a credential helper or SSH deploy keys instead. | Verified by a test that a remote URL with an embedded credential is refused while a credential-free remote passes, and that managed checkouts contain no embedded-credential remotes. |
| `RM-GOVERNANCE-R005` | **Complexity gate scores exhaustive-dispatch functions correctly.** The complexity gate used by repository-manager's quality checks must assign a correct score to functions exempted for exhaustive dispatch, such as pattern matches, rather than scoring them as zero, so that a genuine simplification is never reported as a regression. | Verified by a regression test with an exhaustive-dispatch function that confirms its complexity score reflects its real structure, not zero. |
| `RM-GOVERNANCE-R006` | **Clone-duplication gate enforces zero new pairs before push.** The jscpd clone-duplication gate must report zero new duplicate code pairs, measured against the appropriate base revision, on the final tree before a push is accepted. | Verified by running the duplication gate against the base revision and confirming zero new pairs on the pushed tree. |
| `RM-GOVERNANCE-R007` | **Routine cleanup prunes merged branches and build caches.** repository-manager's cleanup procedure removes checkouts and branches once merge containment is verified and prunes the local package-manager build cache as part of the same routine. | Verified by confirming the cleanup checklist includes a reachability check, a cache-prune step, and a diff review before completion. |
| `RM-GOVERNANCE-R008` | **KISS hook resolves test module path declarations correctly.** The KISS staged-files hook must correctly resolve `mod` declarations in test files, such as `mod support;`, to their actual file paths rather than misreporting them. | Verified by a regression test covering a test file with a `mod` declaration that confirms the hook resolves it correctly. |
| `RM-GOVERNANCE-R009` | **Duplication gate fails closed on an empty-change commit.** When a commit contains only comment or deletion changes that the duplication-detection tool cannot evaluate, the gate must fail closed rather than pass, and such a commit must be combined with the function-level change it belongs to rather than committed alone. | Verified by a test that a comment-only or deletion-only commit is refused by the gate rather than silently passed. |
| `RM-GOVERNANCE-R010` | **Reviewed-distinct clone pairs are tracked in a registry.** A clone pair reviewed and judged genuinely distinct is recorded in the duplication gate's distinct-pairs registry file so the gate does not re-flag it, while clone pairs that represent real duplication are consolidated rather than suppressed. | Verified by confirming each registry entry corresponds to a real, reviewed judgment and that the gate treats only registered pairs as exempt. |
| `RM-GOVERNANCE-R011` | **Status page stays in sync with capability and reservation docs.** Running `scripts/build_status_page.py --write` must regenerate `docs/status.md` so it matches the current content of `docs/capabilities.md`, `docs/capabilities.generated.md`, and `docs/concept_reservations.yaml` with no leftover diff. | Verified by running the status-page builder and confirming it produces no diff against the committed `docs/status.md`. |
| `RM-GOVERNANCE-R012` | **Build verification on extracted trees uses content hashes.** Any verification of a tree extracted by the build runner (which ships source without a `.git` directory) must compare file content against the receipt's own hashes rather than running `git diff` or `git status`, which cannot detect real changes there; the runner should fail loudly if `git` is invoked inside such a tree. | Verified by a test that confirms content hashing detects a real change in an extracted tree where `git diff` reports none. |
| `RM-GOVERNANCE-R013` | **A fast rebase must not silently skip the hook suite.** A `git rebase` that completes in roughly a second must be treated as evidence the pre-commit or pre-push hook suite did not actually run, not as a passing result, and tooling must distinguish a genuine pass from a skipped hook run. | Verified by a test that a rebase skipping hooks is flagged rather than reported as a successful gate run. |
| `RM-GOVERNANCE-R014` | **Completion claims require full hook-run logs as proof.** A claim that quality gates passed must be backed by a complete, non-summary log of the hook run; a pre-commit or pre-push run that was interrupted before completion must not be cited as proof of a pass. | Verified by a check that hook output is captured in full to a log file and that an incomplete run cannot be used to support a pass claim. |
| `RM-GOVERNANCE-R015` | **Continuous review-and-merge replaces batch integration.** Finished work is reviewed and merged to the main branch individually, other active contributors are notified, and they rebase onto the updated main branch, rather than accumulating changes for a single batch integration. | Verified by confirming the written protocol specifies review, merge, notify, and rebase as the standard sequence for each change. |
| `RM-GOVERNANCE-R016` | **Cleanup removes leftover backup references and build scratch.** Routine cleanup removes leftover `refs/backup/*` references and any host-local build scratch directories tied to a finished branch, in addition to the checkout and branch themselves. | Verified by confirming the cleanup checklist enumerates backup-reference and host scratch removal as steps and that none remain after a run. |
| `RM-GOVERNANCE-R017` | **Build submission is asynchronous, not polling-based.** A contributor submits a build to the shared build queue and continues other work rather than polling for its result, with a bounded number of concurrent contributors matched against available build capacity through the queue. | Verified by confirming the build-submission tooling returns immediately after queuing and that a separate notification or log reports the build outcome. |
| `RM-GOVERNANCE-R018` | **Dependency-readiness hook works from any checkout location.** The dependency-readiness pre-commit hook must resolve its paths correctly when run from an isolated branch checkout, not only from the primary repository location, so it does not fail purely due to a relative-path assumption. | Verified by running the hook from an isolated checkout and confirming it passes with exit code zero. |
| `RM-GOVERNANCE-R019` | **A fix is accepted only when all quality gates pass together.** repository-manager accepts a change only when complexity (cccc), KISS, duplication (dupehound), clone-detection (jscpd, zero new pairs), compiler lint (clippy with warnings denied), and the test suite all pass together, not individually. | Verified by a combined gate run that requires every one of these checks to pass before a commit is admitted. |
| `RM-GOVERNANCE-R020` | **Duplication gate distinguishes real new duplication from moves.** The duplication-differential gate must compare against the correct base revision and must not flag code that merely moved to a new file during a refactor as a new duplicate pair when the same fragment already existed in the base tree. | Verified by a test fixture that splits a file without duplicating content and confirms the gate reports zero new pairs against the correct base. |
| `RM-GOVERNANCE-R021` | **Secret-history exceptions are digest-pinned and self-checking.** A historical commit that still matches the secret-pattern scanner, because the pattern is shape-based rather than value-based, is handled through an explicit, digest-pinned exception entry rather than by rewriting history, and that exception mechanism includes a self-check that it still matches only the intended historical occurrence. | Verified by running the scanner's self-check mode and confirming the exception maps exactly to the historical occurrence and no new matches. |
| `RM-GOVERNANCE-R022` | **The repository passes its own full local gate suite.** repository-manager's codebase passes its own complete local pre-commit and pre-push gate suite at its current state, not merely a subset of checks. | Verified by running the full local gate suite end to end and confirming every check passes. |
