# RM-IDENTITY requirements

| ID | Requirement | Verification |
|---|---|---|
| `RM-IDENTITY-R001` | **Rewrite commit identities across public repositories with approval and rollback.** An authorized maintainer can preview, and after explicit signed approval apply, a rewrite of every commit and tag author and committer identity across a selected set of public repositories, mapping the recognized maintainer and coding-agent aliases of the approved identity policy to their canonical identity while holding unclassified identities for explicit review. The rewrite preserves every commit's tree bytes, covers all branches and tags, creates a recoverable backup of the original refs, and publishes to each configured remote only after preview and approval succeed. Rollup of the apply path: the preview half is built (`RM-IDENTITY-R002`, `RM-IDENTITY-R003`, `RM-IDENTITY-R004`, `RM-IDENTITY-R005`) and the rewrite half is specified (`RM-IDENTITY-R006` to `RM-IDENTITY-R009`). Caller chain: a planned apply mode of the existing verb (`repository_manager/governance/cli.py:156`, handler `_history_identity` :566) calls a planned `run_rewrite` in `repository_manager/history_identity/rewrite.py` (planned), which runs `discover` (`repository_manager/history_identity/discovery.py:194`), `generate_preview` (`repository_manager/history_identity/preview.py:157`) and `verify_approval` (`repository_manager/history_identity/approval.py:106`) in that order before any mutation. Shape: `rewrite.py` (planned) holds one `run_rewrite` that composes the built discovery, preview and approval functions with the rows below; no second policy evaluator and no second ref enumerator is added; `IdentityPolicy` (`repository_manager/history_identity/policy.py:125`) stays the only policy type. Writes: backup refs, quarantine refs, then local and remote refs, in the order of `RM-IDENTITY-R007` and `RM-IDENTITY-R008`. Depends: `RM-IDENTITY-R005`, `RM-IDENTITY-R006`, `RM-IDENTITY-R007`, `RM-IDENTITY-R008`, `RM-IDENTITY-R009`. | Test: `tests/test_history_identity_rewrite.py::test_rewrite_preserves_trees_and_backup_refs_restore_history` (planned). It rewrites a fixture repository with a bare remote and restores the original history from the backup refs. |
| `RM-IDENTITY-R002` | **Reconcile diverged history before identity rewrite.** A repository whose local branches share no common ancestor is refused admission to an identity-rewrite plan until its branch history is reconciled into one coherent history. The check is general; applying it to a particular repository is an operational step outside the code. Caller chain: the shell verb `repository-manager-governance history-identity` is parsed at `repository_manager/governance/cli.py:156`, dispatched through `_COMMAND_HANDLERS` (:593) to `_history_identity` (:566), which calls `run_preview` (`repository_manager/history_identity/cli.py:223`), which calls `check_history_consistency` (`repository_manager/history_identity/consistency.py:70`) and `admit_for_rewrite_plan` (:86) per repository inside `_preview_one_repo` (`repository_manager/history_identity/cli.py:144`); a `HistoryConsistencyError` becomes a report with `exit_code` 1 and no preview. Shape: `check_history_consistency` lists `refs/heads/` through `GitRunner.run` (`discovery.py:56`) and asks `git merge-base` for every branch pair through `itertools.combinations`; the result is a frozen `ConsistencyReport` with `DivergedBranchPair` entries. The reconciliation itself (merging or rebasing a diverged branch) is not part of this row. | Test: `tests/test_history_identity_consistency.py::test_check_history_consistency_detects_an_orphan_branch`, `tests/test_history_identity_consistency.py::test_admit_for_rewrite_plan_raises_on_a_diverged_report` and `tests/test_history_identity_cli.py::test_history_identity_cli_refuses_on_diverged_history`. |
| `RM-IDENTITY-R003` | **Complete ref and tag discovery before rewrite.** Before any identity rewrite, the tool enumerates every local ref, annotated and lightweight tag, remote-tracking ref, note ref and signed object in the selected repository set, and refuses to proceed when discovery is incomplete or the repository state is divergent. Caller chain: the shell verb `repository-manager-governance history-identity` is parsed at `repository_manager/governance/cli.py:156`, dispatched through `_COMMAND_HANDLERS` (:593) to `_history_identity` (:566), which calls `run_preview` (`repository_manager/history_identity/cli.py:223`), which calls `discover` (`repository_manager/history_identity/discovery.py:194`) through `_preview_one_repo` (`cli.py:144`). Shape: `discover` runs `_reject_divergent_state` (:124: shallow clone, legacy grafts file, divergent ref prefixes), `_enumerate_refs` (:147: `git for-each-ref refs/`, one `RefRecord` per ref with its kind and `signed` flag from `_is_signed` :137, and a refusal for a ref of no known prefix) and `_enumerate_and_verify_remotes` (:171: `git ls-remote --exit-code` per remote), then returns a `RepositoryDiscovery` whose `digest` (`_digest` :185) is a sha256 over the sorted refs and remotes. Git is called only through the injected `GitRunner` (`SubprocessGitRunner` by default). | Test: `tests/test_history_identity_discovery.py::test_discover_enumerates_branches_tags_remotes_and_notes`, `tests/test_history_identity_discovery.py::test_discover_refuses_hidden_ref`, `tests/test_history_identity_discovery.py::test_discover_refuses_unreadable_ref`, `tests/test_history_identity_discovery.py::test_discover_refuses_unreachable_remote`, `tests/test_history_identity_discovery.py::test_discover_refuses_shallow_clone`, `tests/test_history_identity_discovery.py::test_discover_detects_a_signed_commit` and `tests/test_history_identity_cli.py::test_history_identity_cli_refuses_on_incomplete_discovery`. |
| `RM-IDENTITY-R004` | **Deterministic dry-run identity rewrite plan.** The tool produces a deterministic dry-run plan mapping old identities to new ones and old refs, commits and tags to their rewritten equivalents, reporting counts, affected authors and committers, unchanged tree digests and any collision warnings. Caller chain: the shell verb `repository-manager-governance history-identity` is parsed at `repository_manager/governance/cli.py:156`, dispatched through `_COMMAND_HANDLERS` (:593) to `_history_identity` (:566), which calls `run_preview` (`repository_manager/history_identity/cli.py:223`), which calls `build_policy` (`repository_manager/history_identity/policy.py:193`) and `generate_preview` (`repository_manager/history_identity/preview.py:157`) through `_preview_one_repo` (`cli.py:144`) and renders `_preview_report` (:160). Shape: `generate_preview` lists every commit of `git log --all` (`_enumerate_commits` :85), resolves author and committer through `IdentityPolicy.resolve` (`policy.py:166`; exact name and email only, an unmatched identity resolves to `None`), records `signed_shas` from the discovery, warns per unmapped identity in `_collision_warnings` (:120), and folds the discovery digest, the policy digest, the remotes and the expiry into the plan `digest` (:134). The plan lists identity mappings per commit; the old-to-new commit, tag and ref maps and the tree digests belong to the rewrite engine of `RM-IDENTITY-R006`, which computes them. Depends: `RM-IDENTITY-R003`. | Test: `tests/test_history_identity_preview.py::test_generate_preview_is_deterministic_across_runs`, `tests/test_history_identity_preview.py::test_generate_preview_digest_changes_when_source_mutates`, `tests/test_history_identity_preview.py::test_generate_preview_surfaces_collision_warning_for_unmapped_identity`, `tests/test_history_identity_preview.py::test_generate_preview_folds_policy_digest_and_is_sensitive_to_policy_change`, `tests/test_history_identity_cli.py::test_history_identity_cli_output_is_deterministic_across_two_runs` and `tests/test_history_identity_cli.py::test_history_identity_cli_surfaces_unmapped_identity_without_refusing`. |
| `RM-IDENTITY-R005` | **Signed approval required before any rewrite.** The rewrite only runs after a signed or otherwise authenticated approval that is bound to the exact repository set, source ref digests, identity policy digest, target remotes and an expiry time. Caller chain: the shell verb `repository-manager-governance history-identity` is parsed at `repository_manager/governance/cli.py:156`, dispatched through `_COMMAND_HANDLERS` (:593) to `_history_identity` (:566), which calls `run_preview` (`repository_manager/history_identity/cli.py:223`), which, when `--approval` is given, calls `_verify_approval_or_refusal` (`repository_manager/history_identity/cli.py:184`) and `verify_approval` (`repository_manager/history_identity/approval.py:106`) with the key read from the environment variable named by `--approval-key-env` (default `RM_HISTORY_IDENTITY_APPROVAL_KEY`). Shape: `ApprovalBinding` (`approval.py:27`) holds the sorted repository IDs, the combined source digest (`_combined_source_digest` `cli.py:119`), the policy digest, the sorted remotes and the expiry; `verify_approval` checks the binding (`_reject_if_unbound` :79), the expiry (`_reject_if_expired` :92) and an HMAC-SHA256 signature compared with `hmac.compare_digest` (`_reject_if_forged` :100), in that order, and any `ApprovalError` becomes a refusal with `exit_code` 1. The signature mechanism is an HMAC over a shared key; a different authenticated mechanism is an owner decision. Depends: `RM-IDENTITY-R004`. | Test: `tests/test_history_identity_approval.py::test_verify_approval_accepts_a_valid_matching_signature`, `tests/test_history_identity_approval.py::test_verify_approval_rejects_missing_approval`, `tests/test_history_identity_approval.py::test_verify_approval_rejects_expired_approval`, `tests/test_history_identity_approval.py::test_verify_approval_rejects_a_forged_signature`, `tests/test_history_identity_approval.py::test_verify_approval_rejects_the_wrong_key`, `tests/test_history_identity_cli.py::test_history_identity_cli_refuses_on_a_missing_approval_key` and `tests/test_history_identity_cli.py::test_history_identity_cli_refuses_an_approval_bound_to_a_different_plan`. The rewrite-side proof that a refused approval performs zero mutations, `tests/test_history_identity_rewrite.py::test_missing_expired_or_altered_approval_mutates_nothing`, is planned. |
| `RM-IDENTITY-R006` | **Byte-identical trees and preserved history topology.** Every rewritten commit keeps a byte-identical tree object and preserves its parent order, message and timestamp, and tag payload semantics are preserved where possible; a signed commit or tag is rewritten only when the approval for that run explicitly authorizes re-signing, and otherwise it is reported and left unchanged. Caller chain: planned `run_rewrite` (`repository_manager/history_identity/rewrite.py`, planned; see `RM-IDENTITY-R001`) calls a planned independent verifier `verify_rewrite` in `repository_manager/history_identity/verify.py` (planned) after the quarantined rewrite and before the local ref update of `RM-IDENTITY-R007`. Shape: `verify.py` (planned) compares every old and new commit with `git rev-parse <sha>^{tree}`, the parent list and the message and timestamps, using `GitRunner` (`repository_manager/history_identity/discovery.py:56`) and the `signed_shas` already recorded by `HistoryPreview` (`repository_manager/history_identity/preview.py:63`); it shares no code with the rewrite function so the engine cannot grade its own output. Refusals: a mismatch stops the run before any ref update. Depends: `RM-IDENTITY-R004`. | Test: `tests/test_history_identity_verify.py::test_every_rewritten_commit_keeps_tree_parents_message_and_timestamps` (planned). It covers merges with several parents, author and committer aliases and annotated tags. |
| `RM-IDENTITY-R007` | **Quarantined staging with backup refs before ref update.** Before updating any ref, the tool writes immutable, collision-safe backup refs and a durable object map, stages the rewritten refs in quarantine, verifies their reachability, and only then updates each repository's refs atomically. Caller chain: planned `run_rewrite` (`repository_manager/history_identity/rewrite.py`, planned) calls a planned `stage_and_update` in `repository_manager/history_identity/transaction.py` (planned) after `verify_rewrite` of `RM-IDENTITY-R006` passes. Shape: `transaction.py` (planned) creates the backup namespace and the quarantine namespace with `git update-ref --stdin` batches through the injected `GitRunner` (`repository_manager/history_identity/discovery.py:56`), writes the object map as a content-addressed file, and applies the final ref update as one `update-ref --stdin` transaction with expected old values; a failure before that transaction removes only quarantine refs. Backup refs are never deleted by this change. Depends: `RM-IDENTITY-R006`. | Test: `tests/test_history_identity_transaction.py::test_failure_before_update_leaves_old_refs_and_backups_restore_after_update` (planned). |
| `RM-IDENTITY-R008` | **Lease-protected per-remote publication receipts.** Publication to each configured remote uses a lease-protected ref update and records a per-remote outcome receipt, and the tool never reports fleet-wide success when any remote publication is only partially complete. A protected ref that rejects the update is reported as refused for that remote; the tool never lifts branch protection. Caller chain: planned `run_rewrite` (`repository_manager/history_identity/rewrite.py`, planned) calls a planned `publish_remotes` in `repository_manager/history_identity/publish.py` (planned) after the local transaction of `RM-IDENTITY-R007`. Shape: `publish.py` (planned) runs `git push --force-with-lease=<ref>:<expected old sha>` per ref and per remote through `GitRunner` (`repository_manager/history_identity/discovery.py:56`), takes the expected old values from the `RepositoryDiscovery` (`discovery.py:108`) bound by the approval, and returns one receipt per remote with the states complete, partial, refused or pending plus reconciliation instructions. Depends: `RM-IDENTITY-R007`. | Test: `tests/test_history_identity_publish.py::test_remote_drift_and_rejected_branch_yield_partial_receipt_not_success` (planned). |
| `RM-IDENTITY-R009` | **Coordinated merge-queue pause and resync during rewrite.** While a rewrite is in flight, the tool pauses active merge queues, notifies and refreshes open pull-request branches and forks, and resynchronizes release baselines, resuming queue activity only after remote and CI verification confirm the new history. Caller chain: planned `run_rewrite` (`repository_manager/history_identity/rewrite.py`, planned) calls the merge queue through `merge_queue.dispatch` (`repository_manager/merge_queue.py:3621`), whose action table (:3626) has no pause action today. Shape: `pause` and `resume` are two explicit queue operations: two planned rows join that table beside `enqueue`, `status`, `withdraw`, `run` and `config`, each with one implementation, one CLI verb and, through the per-action split of the queue tool, one MCP tool (`rm_merge_queue_pause`, `rm_merge_queue_resume`); while paused, `run_queue` (:3583) and `enqueue` (:802) refuse a candidate based on the pre-rewrite history. Notifying contributors and refreshing open pull-request branches and forks has no existing helper (`repository_manager/forge_status.py` reads hosted CI status only); the notice channel, its wording and the branch refresh mechanism are an owner decision. Depends: `RM-IDENTITY-R008`. | Test: `tests/test_history_identity_coordination.py::test_no_queued_candidate_merges_against_stale_history` (planned). |
