# RM-IDENTITY-001 requirements

| ID | Requirement | Verification |
|---|---|---|
| `RM-IDENTITY-R001` | **Rewrite commit identities across public repositories with approval and rollback.** An authorized maintainer can preview, and after explicit signed approval apply, a rewrite of every commit and tag author/committer identity across a selected set of public repositories, mapping recognized maintainer, Claude (`Claude <noreply@anthropic.com>`), and Codex (`Codex <codex@users.noreply.github.com>`) aliases to their canonical identity while holding unclassified identities for explicit review. The rewrite preserves every commit's tree bytes, covers all branches and tags, creates a recoverable backup of the original refs, and publishes to each configured remote only after preview and approval succeed. | A verification run compares old and new commit tree digests for byte-for-byte equality and confirms the backup refs can restore the original history before any live rewrite is approved. |
| `RM-IDENTITY-01` | **Complete ref and tag discovery before rewrite.** Before any identity rewrite, the tool enumerates every local ref, annotated and lightweight tag, remote-tracking ref, and signed object in the selected repository set, and refuses to proceed when discovery is incomplete or the repository state is divergent. | A fixture containing a hidden ref, a detached tag, or an unreachable remote demonstrates the tool refuses to execute rather than operating on partial discovery. |
| `RM-IDENTITY-02` | **Deterministic dry-run identity rewrite plan.** The tool produces a deterministic dry-run plan mapping old identities to new ones and old refs, commits, and tags to their rewritten equivalents, reporting counts, affected authors and committers, unchanged tree digests, and any collision warnings. | Running the preview twice against the same source yields an identical plan digest, while any change to the source invalidates a previously granted approval. |
| `RM-IDENTITY-03` | **Signed approval required before any rewrite.** The rewrite only runs after a signed or otherwise authenticated approval that is bound to the exact repository set, source ref digests, identity policy digest, target remotes, and an expiry time. | A fixture with a missing, expired, or altered approval shows the tool performs zero mutating operations. |
| `RM-IDENTITY-04` | **Byte-identical trees and preserved history topology.** Every rewritten commit keeps a byte-identical tree object and preserves its parent order, message, and timestamp, and tag payload semantics are preserved where possible; a signed commit or tag is only re-signed after an explicit decision to do so. | An independent verifier compares every old and new tree object and graph invariant, including parent order, messages, and timestamps, and confirms they match. |
| `RM-IDENTITY-05` | **Quarantined staging with backup refs before ref update.** Before updating any ref, the tool writes immutable, collision-safe backup refs and a durable object map, stages the rewritten refs in quarantine, verifies their reachability, and only then updates each repository's refs atomically. | A simulated failure injected before the update leaves the original refs untouched, and after a completed update the backup refs can reconstruct the prior history. |
| `RM-IDENTITY-06` | **Lease-protected per-remote publication receipts.** Publication to each configured remote uses a lease-protected ref update and records a per-remote outcome receipt, and the tool never reports fleet-wide success when any remote publication is only partially complete. | A fixture with remote drift, a rejected protected branch, or one remote outage produces a partial or pending status with reconciliation instructions rather than a false success. |
| `RM-IDENTITY-07` | **Coordinated merge-queue pause and resync during rewrite.** While a rewrite is in flight, the tool pauses active merge queues, notifies and refreshes open pull-request branches and forks, and resynchronizes release baselines, resuming queue activity only after remote and CI verification confirm the new history. | A rehearsal demonstrates that no pending candidate is merged against the stale pre-rewrite history. |
| `RM-IDENTITY-R002` | **Reconcile diverged history before identity rewrite.** Before the fleet-wide identity rewrite in this specification can include the agent-webui repository, its diverged branch history must be reconciled into one coherent history that the rewrite plan can operate on. | A reconciliation check confirms the repository's branches share one consistent commit history before it is admitted to an identity-rewrite plan. |
