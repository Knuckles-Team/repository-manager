# RM-CONNECTOR requirements

| ID | Requirement | Verification |
|---|---|---|
| `RM-CONNECTOR-R001` | **Migrate connector imports to the public SDK boundary.** repository-manager keeps its existing Git, branch-management and release tooling in place and reaches connector transport only through the public scion-sdk API, keeping any orchestration-package import only at the boundary where an actual orchestration decision is made. Caller chain: the console script `repository-manager-mcp` (`pyproject.toml:53`) runs `mcp_server` (`repository_manager/mcp_server.py:1002`), which calls `get_mcp_instance` (:973); that builds the server with `create_mcp_server` and `register_tool_surface` (:33, :988) from `scion_sdk.mcp`, and the tool registrars in `repository_manager/mcp_tools/` import `scion_sdk.mcp.action_dispatch.resolve_action` and `scion_sdk.mcp.concurrency.run_blocking`. Shape: no module under `repository_manager/` imports a private SDK module or the orchestration package; the dependency is declared once as `scion-sdk[mcp]` in `pyproject.toml:12`. Depends on: `RM-CONNECTOR-R003`. | Test: `tests/test_mcp_registration.py::test_mcp_tools_registration` and `tests/test_adapter_extraction.py::test_registry_order_and_extension_seam_are_deterministic`. |
| `RM-CONNECTOR-R002` | **Classify every import from the orchestration package.** repository-manager inventories every production and test import drawn from the orchestration package and classifies each as orchestration, connector transport, governance or obsolete. Caller chain: a planned inventory script `scripts/check_import_inventory.py` (planned), run by a `local` hook in `.pre-commit-config.yaml`, walks `repository_manager/` and `tests/` with `ast`, as `scripts/check_import_safety.py` does for platform imports. Shape: the inventory is a machine-readable JSON file `scripts/import_inventory.json` (planned) with one record per import holding module, symbol, caller and one of the four classes; a dynamic import (`importlib.import_module`) with a non-literal name is a failure, not a class. Today no import from the orchestration package exists in the code, so the inventory is empty and the check asserts that. The four class names and the file location are accepted as written here. | Test: `tests/test_import_inventory.py::test_every_orchestration_import_has_one_disposition_and_none_is_dynamic` (planned). |
| `RM-CONNECTOR-R003` | **Route connector transport imports through the public SDK.** Imports classified as connector transport call the public scion-sdk API, and imports of the orchestration package remain only at the boundary where repository-manager makes an orchestration decision. Caller chain: every MCP tool registrar in `repository_manager/mcp_tools/` imports from `scion_sdk.mcp.*` (`action_dispatch`, `concurrency`, `tool_surface`, `server`, `content`) and from `scion_sdk.config`, `scion_sdk.file_lock`, `scion_sdk.utilities`, `scion_sdk.privacy` and `scion_sdk.tls`, all public modules of the package. Shape: the tool entry points execute through `register_tool_surface` and `resolve_action`; the retired private governance module `scion_sdk.governance.lanes` and its package are imported by no production module. Depends on: `RM-CONNECTOR-R001`. | Test: `tests/governance/test_no_parallel_lane_authority.py::test_no_production_module_imports_the_retired_lane_module` and `tests/test_mcp_registration.py::test_mcp_tools_registration`. |
| `RM-CONNECTOR-R004` | **Keep governance imports under repository-manager authority.** Development-governance imports such as queueing, reservation and safe-commit stay under repository-manager's own authority (`RM-GOVERNANCE-R001`) rather than being routed back through the orchestration package. Caller chain: the lane, queue, reservation and commit tools call `LaneRegistry` (`repository_manager/lane_registry.py:648`), `merge_queue.dispatch` (`repository_manager/merge_queue.py:3621`), `concept_actions.dispatch` (`repository_manager/concept_actions.py:124`) and `safe_commit` (`repository_manager/safe_commit.py:613`). Shape: the governance package is `repository_manager/governance/`; `tests/governance/test_no_parallel_lane_authority.py` scans every production module outside it for the retired governance import. Depends on: `RM-GOVERNANCE-R001`. | Test: `tests/governance/test_no_parallel_lane_authority.py::test_the_packages_own_lane_module_is_the_live_implementation`, `tests/governance/test_no_parallel_lane_authority.py::test_concept_reservation_module_is_hosted_as_this_packages_own` and `tests/governance/test_no_parallel_lane_authority.py::test_no_production_module_imports_the_retired_lane_module`. |
| `RM-CONNECTOR-R005` | **Preserve MCP/CLI contract during connector migration.** The migration preserves every public MCP and CLI action name, its typed arguments, validation rules and error categories, or introduces an explicitly versioned, documented change. Caller chain: a client lists the tools of the server built by `get_mcp_instance` (`repository_manager/mcp_server.py:973`); the catalog is the tool list that `register_split_action_tools` and `register_tool_surface` (:988, :994) produce, and the actions are validated by `resolve_action` against the tuples of `repository_manager/mcp_tools/contracts.py`. Shape: the golden is the sha256 of the sorted tool catalog (`BASELINE_CATALOG_SHA256` in `tests/test_adapter_extraction.py`) together with `repository_manager/connectors/tool_schema_fingerprints.json`; a change of either is a reviewed, versioned migration. Depends on: `RM-CONNECTOR-R001`. | Test: `tests/test_adapter_extraction.py::test_per_operation_mcp_catalog_matches_contract` and `tests/test_skill_action_surface.py::test_skill_action_references_match_live_schema`. |
| `RM-CONNECTOR-R006` | **Remove dead connector adapters after cutover.** Once the new connector path passes its tests, repository-manager removes the dead adapters, duplicate publishers and fallback imports that supported the old path. Caller chain: the package build (`uv build` over `pyproject.toml`) and the `check-cli-help` hook of `.pre-commit-config.yaml` import and start `repository_manager.mcp_server` without any retired module. Shape: the source scan is the parametrized test over every production file in `tests/governance/test_no_parallel_lane_authority.py`. Depends on: `RM-CONNECTOR-R003`, `RM-CONNECTOR-R004`. | Test: `tests/governance/test_no_parallel_lane_authority.py::test_no_production_module_imports_the_retired_lane_module`. The retired-name scan of the whole package, `tests/test_retired_names.py::test_no_retired_package_name_in_production_code` (planned), extends it beyond governance. |
